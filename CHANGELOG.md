### Changed

- TikZ externalization: a figure is rebuilt when a `\tikzset`/`\pgfplotsset` style outside pictures (also in chapters), a macro or colour it uses, or a file it `\input`s changes, not only the preamble. `accel.py` is a build input, so every document rebuilds once.
- `publish_release.py` uploads only the files of documents (each PDF and log, `[[output]]` PDFs and logs, and `<name>.html.zip` for `html = true`), never other files in `out/` (review, latexdiff, chapter preview or `--pages` PDFs).

### Fixed

- MCP `render_page` with mutool (no pdftoppm) made portrait pages taller than `size`; the longest side is now `size`, as with pdftoppm.
- Hosted: a Git sync (`/p/<id>/api/git/remote`) and `/api/people`, `/api/access/*` were answered by the gateway and then also relayed to the project's worker, which started it and wrote a second reply on the same connection.
- Hosted Git tab: the result of a pull (the list of files that differ) was cleared at once by the panel's refresh, so conflicts were never shown.
- Hosted Git sync: refused and failed pulls and pushes (wrong token, rejected push, size cap, timeout) are audited too (`git_pull`/`git_push` with `failed: <status>`).
- Editor sidebar: with every tab shown (Symbols, Assistant, Git) the tabs ran under the editor, so Git and the close button could not be clicked; they wrap now.
- Accessibility: the Git panel's diff is keyboard-scrollable, and the PDF viewer has a region role for its label (axe `scrollable-region-focusable`, `aria-prohibited-attr`).
- A `.bib` outside the document's directory (`\bibliography{../shared/refs}`, `\addbibresource`) now counts for rebuild detection (local and CI `--changed-since`) and `--deps`: BibTeX and biber read it, so it was never in the `.fls`; it is now taken from latexmk's `.fdb_latexmk`. `build.py` changed, so every document rebuilds once.
- A build that fails without a LaTeX error to show (an empty document body: "No pages of output", or latexmk failing outright) now says why in the summary, `build-report.json`'s `error`, the CI table and the editor, instead of a bare FAILED.
- Comment and reply boxes with @-completion (suggestion card, Review panel) no longer point `aria-controls` at a people list that is not in the page yet (axe `aria-valid-attr-value`).
- Browser checks: axe-core now also covers Account > API tokens (`host_e2e.py`), the suggestion card and the bell (`review_e2e.py`), and the snippets, figure, table and TikZ dialogs and the Git panel (`nav_e2e.py`).
- Files of Debian's `/usr/share/texmf` and `TEXMFDIST` no longer count as a document's inputs outside its directory (`TEXMFDEBIAN` and `TEXMFDIST` added to the TeX tree variables).

## [0.1.0] - 2026-10-12

### Fixed

- `build.py`, `serve.py` and `mcp_server.py` with `--source` outside the repository (absolute, or relative like `../../elsewhere`) no longer crash (`ValueError` in `cache_dir_for`, `--new`, `--list`, forward search): the cache is keyed by a hash of the directory's path (`.latex-cache/_x<hash>_2F<doc>`; casefolded on case-insensitive file systems, so `serve.py` and `mcp_server.py` agree on rooms and history whatever casing they were given), outputs go to `out/`, paths outside the repository are shown absolute, `--changed-since` is ignored for them with a note. Version history of such documents moves to that key too (it used to share `.latex-history/<doc>` with `files/<doc>`); an existing `.latex-history/<doc>` is adopted on first use unless `files/<doc>` exists. In-repository cache names are unchanged.
- A document that only mentions `tikz` or `pgfplots` in its text no longer fails with `Extra \fi` at `\begin{document}`: the externalization hook keeps `\ifpgf@external@grabshipout` out of skipped branches, and TikZ is detected from `\usepackage`/`\RequirePackage` (tikz, pgf, pgfplots and packages built on them), `\documentclass[tikz]`, `\usetikzlibrary`/`\usepgfplotslibrary`, `\tikz` or `tikzpicture` outside comments instead of any mention of the word.
- Live preview: labels a chapter defines and citations of keys the full build never cited resolve in the same preview (up to 3 passes, BibTeX sandboxed; 1.5 s and 2.2 s on `bench/sample-report` instead of `??` / `(?)` at 0.7 s); `main.tex` body edits preview the part between two chapters (0.2 to 0.4 s), edits of the preamble, a `.cls`/`.sty` or the `\input` list pause the preview with "rebuilding preamble" until the full build instead of showing stale pages; pages are placed from the `.focusmap`'s shipped-page counts (`\pgff@s`), so the splice works without hyperref, and chapters after an uncleared page are numbered like the full PDF (also in `--focus`); double-click on preview pages (SyncTeX of the preview, `/synctex/edit?preview=`); `\include`d chapters and package-read files are typeset from the unsaved text; full builds run at nice 10 (and their Linux autogroup) and figure jobs wait while a preview typesets (worst previews 0.4 to 0.7 s shorter under a forced rebuild, medians unchanged).
- Partial figure listing reads a file whose pictures a macro draws instead of skipping it (a changed macro could leave figure numbers wrong).
- A figure edit no longer trusts a stale `.focusmap` (wrong `\thesection` baked into a cached figure); a deleted input or a folder change makes the PDF stale; files reached through a symlinked folder inside a document directory are tracked; `--focus` and figure jobs work in tagged documents.

### Added

- **Streamed AI answers** (`ai.ask_stream`, `POST /api/ai?stream=1`, NDJSON): the editor shows the answer while the model writes it (the server decodes only the `answer` field from the partial JSON; text and edits stay unseen until the whole reply passes `parse_reply`), with a Stop button that closes the upstream request; diff and Apply only for the final checked reply; a broken connection is reported, never retried (no double billing). Hosted, the gateway streams and records usage however the stream ends. Mid-stream errors, refusals, cut-offs and timeouts end in an in-band error.
- AI limits: shared-link guests have their own cap (20 an hour per named link, or per anonymous link and address) besides the 100 per server run; hosted, each request reserves a whole reply against the token budget until its usage is known (a stopped stream keeps the reservation), and requests Anthropic did not bill are given back.
- Version history no longer fills up: unnamed versions thin out with age on every new version (all for 24 h, then one per file per hour for 7 days, one per day for 90 days, one per week; at most 500 rows per write), named versions, each file's newest text and the text before a deletion are never thinned, and blobs nothing uses are deleted. The caps stay as a last resort, and a full history is now shown in the History tab. **Clean up** in the History tab deletes versions older than a chosen age (named ones only when ticked) and Delete removes a named version, after a confirmation and without undo: the local owner, or behind the gateway a workspace admin (`host.py` adds `X-Host-Admin: 1`, which the worker accepts only with its secret; share links never). New `POST /api/history/clean`. The sqlite index is now charged against the hosted quota as well (`review.json` already was).
- Restoring files open in co-editing is atomic from the server's view: the server writes the other files and records a pending restore per open file first; one editor in the room claims it (`GET/POST /api/history/pending`, one claimer at a time), applies it as one edit and sends `restore-done` on the bus after its Yjs update, so a second restore of the same file is claimed only once the first is in. A claim from a browser that closed, or older than 30 s (a lost `restore-done`), is released for the next editor, who finds it already applied or applies it; it is applied only as the change from the text it replaced, so edits made in between are never reverted (the restore is skipped instead). The server writes what is still pending when no editor has the file open (viewers alone do not hold it), only while the file is unchanged since the restore and its text is in the history, and checks of pending restores have their own rate bucket.
- **Named share links** (`scripts/share_links.py`, `serve_ui/links.js`, Share dialog): the owner makes a link per person with a name and a role (edit or view); each has its own token, and the server takes comments', suggestions', history authors' and presence names from the link (the same `id;name` identity as a hosted account), never from the request. Anonymous view/edit links keep working, their names shown as "(unverified name)". Revoke ends the link's sessions at once (WebSocket closed, long-poll answered 401, client records and rooms dropped, cookie cleared on the next request); "New links" replaces only the anonymous pair. Records in `share-links.json` (format version 2) in the owner's config folder, mode 600, outside every document; each link is bound to its document's name and checkout (resolved `main.tex` path), re-read when the file changes (a revoke from another editor process holds at once), and valid for later shares of that document. Owner-only `POST /api/share/links`, `/api/share/links/revoke`; `GET /api/share` lists them (owner only). Ignored in `--gateway` mode.
- Suggest mode: IME composition (CJK, dead keys, phone keyboards) becomes a suggestion; while composing, the room holds the local text back from co-editors and the disk (`Room.hold`) and others' edits, rejoins, disk merges and history restores wait or are refused (so does accepting a suggestion), for at most 5 s, ending on blur or a hidden tab; a composition the shared text moved under is dropped, never published; the held composition is not tracked by the shared undo manager, so no tombstone carries its text. One multi-cursor edit is one grouped suggestion (`more` ranges in `review.py`, `partsOf` / `placeGroups` in `anchors.js`), accepted or rejected as a whole and re-anchored per range. Ctrl+Z / Ctrl+Y in suggest mode undo and redo your own drafts and suggestions (shorten, drop, withdraw, re-suggest) instead of being disabled in shared rooms. Remote changes are recognised by the Yjs transaction in progress (`Room.yTx`) instead of the missing-user-event heuristic. `tests/review_e2e.py` checks all of it in Chromium with an owner and two named guests.

### Security

- DOCX export is owner-only (`GET /docx/<doc>` too) and refused while sharing: pandoc follows `\input{../x}` and `\lstinputlisting{/abs/path}` into the .docx, so a shared source could leak files.
- `bibfix.parse` is linear on unterminated braces (a 64 KB input took ~30 s); `POST /api/bib/lookup` refuses text over 1 MB.
- Shared (non-owner) Crossref lookups use their own limit (10 per minute), so they cannot use up the owner's quota.
- While sharing, treat every non-owner as hostile: tokens on every request (loopback included), builds run with `-norc`, `shell_escape=f`, `openin_any=p`, `openout_any=p`, unsafe `latexmk_args` rejected, builds time out after at most 300 s and are rate limited (6 a minute).
- View and edit roles enforced in the API and message bus: no cross-document messages, `build.toml` and `latexmkrc` owner-only (also in live rooms), uploads magic-byte checked, per-client and per-room caps, Content-Security-Policy with pinned CDNs, Host header check.
- Grammar: the public API is never chosen automatically, needs confirmation, `GRAMMAR_PUBLIC_OK=1` in CI and the owner's permission while sharing; requests are chunked and throttled.
- Hardened file operations in the editor server.
