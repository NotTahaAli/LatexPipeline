# AGENTS.md

`README.md` covers usage; `python scripts/build.py --help` lists flags.

## Layout

- `files/<name>/main.tex` is one document, built to `out/<name>.pdf`. Only directories under `files/` are searched by CI and by default. `bench/` holds local benchmark documents, built with `--source bench`; CI never builds them, and `build.py` keeps their outputs in `out/` when it prunes.
- A document's inputs are everything in its own directory. Keep `.cls`, `.bib`, and figures beside `main.tex`. Files outside it (`\input{../shared/x}`) count for rebuild detection (local mtime and CI `--changed-since`) once a build has recorded them in the document's `.fls` (latexmk `-recorder`, in `.latex-cache/`). A document's first build sees only its own directory.
- `out/` is generated and git-ignored. Every build writes `out/<name>.log`, which holds the result plus the latexmk, LaTeX and BibTeX logs. `build.py` also deletes PDFs and logs whose `main.tex` is gone.
- CI publishes to the GitHub release tagged `pdfs` through `scripts/publish_release.py`. That tag is also the bookmark CI diffs against, so treat it as CI-owned. Moving or deleting it by hand changes what the next run rebuilds.

## Build script

- `scripts/build.py` uses only the Python standard library and must keep working on Windows, macOS, and Linux. Reach for stdlib before adding a dependency.
- `scripts/accel.py` holds the TikZ externalization and `--focus` helpers `build.py` imports (pretex files injected through `latexmk -usepretex`). Keep it stdlib-only and cross-platform too; every accelerated path must fall back to a plain build.
- `scripts/sandbox.py` (stdlib-only) is the one runner for LaTeX: every subprocess that runs latexmk, a TeX engine or bibtex/biber (builds, figure jobs, `--focus`) gets its arguments from `sandbox.spawn()` and calls `sandbox.scrub()` on the writable directory once it ends. With `LATEX_SANDBOX=bwrap` (`--sandbox`, hosted workers) that is bubblewrap; a required but unusable sandbox fails the build and must never fall back to an unsandboxed run. Outside it run only `ci_report.py diff` (CI, the repository's own documents) and tools that do not execute LaTeX (`kpsewhich`, `synctex`, `texcount`, veraPDF, owner-only pandoc). Prove new confinement in `tests/test_sandbox.py`.
- `scripts/publish_release.py` runs only in CI. It imports from `build.py` and calls the `gh` CLI. It uploads the PDFs and logs in `out/`, so in CI `out/` must hold only this run's output. A failed document then keeps its previous PDF next to the new `.log`. Release file names use reversible `_XX` hex escaping (`asset_name`), and deletion relies on that mapping. Change the naming rule and every existing file on the release gets deleted and re-uploaded under its new name on the next run. The release notes keep their per-document state in a hidden `<!-- latex-pipeline-state: ... -->` comment, so changing that format loses the "PDF from" column for documents not rebuilt in the next run.
- `scripts/serve.py` and `scripts/serve_ui/` are the local editor; CI never runs them. `serve.py` is stdlib-only, cross-platform and must keep working on Python 3.9 (`from __future__ import annotations`; no `match`, no `X | Y` outside annotations). The UI loads libraries only from the pinned URLs in the import map of `index.html` (exact versions; `libs.js` and `pdf.js` use bare names) and the CSP (`csp()`). `scripts/vendor_ui.py` (stdlib-only, git-ignored output in `serve_ui/vendor/`) downloads them for offline use: when `vendor/manifest.json` exists, `serve.py` rewrites the import map to `/ui/vendor/...`, serves only files the manifest lists, and the CSP drops the CDN origins. Bump a version in the import map only, then re-run the script. Do not import `serve` from `build.py`, `ci_report.py` or `publish_release.py`, and keep editor-only files out of `GLOBAL_INPUTS` and the workflow `paths:`. While sharing is on, treat every non-owner as hostile: LaTeX source is code. Builds get `-norc`, `shell_escape=f`, `openin_any=p`, `openout_any=p` and no unsafe `latexmk_args` (`guarded_read_settings`, `unsafe_latexmk_arg`, `SHARE_ENV`). LuaLaTeX stays allowed by the owner's choice (Lua can write files, so an edit link can run code); the Share dialog must keep saying so; build-config files (`RC_NAMES`) stay owner-only in the PUT API and in Yjs rooms; `visible()` is a whitelist that filters bus messages by document and room; new endpoints and bus message types go through `check_permission` and `visible()`, with a test. Decisions that protect data (leader takeover, deleted files) are made server-side or covered by `tests/collab_check.mjs`.
- `scripts/history.py` (version store) and `scripts/review.py` (comments, suggestions) are stdlib-only, Python 3.9, imported by `serve.py` only. Their data lives in `.latex-history/<doc>/` beside the build cache, never in the document directory (no build input, no zip export, not in `GLOBAL_INPUTS`); behind the gateway it counts toward the quota through `store_allows`, and a failing history write never fails a save. Reading needs the view role (`READ_API`), changing needs the edit role; non-owners never see or restore `RC_NAMES` files; their bus messages (`history`, `review`) carry only the document name and go through `visible()`. Unnamed versions thin out by age on every record (`THIN`, at most `THIN_BATCH` rows); thinning, pruning and clean-up never remove named versions (clean-up only when asked), a file's newest row or the text before a deletion, and blobs nothing refers to are deleted (at the caps history raises `Full`, stops and the panel says so); index rows are charged against `room()` like blobs. Deleting versions (`POST /api/history/clean`) is for the local owner or, behind the gateway, a workspace admin (`X-Host-Admin: 1` from `host.py`, honoured only with the worker secret and the edit role), never a share link; a `?cid=` counts only through `trusted_client`; review data that cannot be read is an error, never "empty". The server never writes a file that has an open co-editing room: accepted suggestions go through the requesting editor (accept claims the suggestion server-side first); a restore records a pending entry per room file before writing the rest, one room member claims it (`history.Store.claim`, one claimer at a time), applies it as one edit and sends `restore-done` on the bus after its Yjs update; lapsed claims are released and the server writes what is left once the room is empty (`finish_pending`, from housekeeping). User text in the UI only via `textContent`. Anchor logic (`serve_ui/anchors.js`) is checked by `tests/collab_check.mjs`.
- `scripts/preview.py` (stdlib-only, Python 3.9, imported only by `serve.py`; editor-only like `serve_ui/preview.js`) is the live preview: one TeX process per document waits at `\begin{document}` and typesets the `--focus` chapter with the editor's unsaved text. Every process starts through `sandbox.spawn()` on its one spawner thread (bwrap's `--die-with-parent` follows the thread that started it, and HTTP threads end with their request) and its directory is scrubbed after it ends. A waiting process is used only while `preamble_key()` matches, which includes the sharing variables and `LATEX_SANDBOX`; add anything else that changes how TeX runs to that key. Cross-references come from the snapshot `serve.refresh_preview()` takes after a good full build, never from a build directory being written. Tests: `tests/test_preview.py`; in the browser `tests/preview_e2e.py` (latency, splice, cancellation, axe).
- `scripts/host.py` (+ `scripts/host_ui/`) is the hosted gateway: stdlib-only, Python 3.9, serving Linux-only, but `tests/test_host.py` must pass on Windows and macOS (skip what needs bwrap or LaTeX) and never touches the network (mock `host.http_json` and `ai.post_json`, the only outbound calls). Threat model: every signed-in user, workspace admins included, is hostile; only the operator (shell, `config.toml`, site admin) is trusted, and nothing reachable from the web may make the server run code outside the sandbox. Workers are `serve.py --gateway`: loopback, `LATEX_SANDBOX=bwrap`, a minimal environment, and they trust only the per-worker `X-Host-Secret`; the proxy forwards a whitelist of request headers (`FORWARD`), so client `X-Host-*`, cookies and `X-Forwarded-*` never reach a worker. Every route is registered with `route(method, pattern, need)`; state-changing requests need the same Origin and (with a session) the `X-CSRF-Token`; a project or workspace the user cannot reach answers 404, not 403. New endpoints and role checks need a test in `tests/test_host.py`; schema changes are a new entry appended to `MIGRATIONS`, never an edit of an old one. Keep the UI on `'self'` only (no inline script or style, no CDN) and run `tests/host_e2e.py` (axe 0 violations) after UI changes.
- `scripts/fonts/` holds the UI typefaces (Newsreader, Source Sans 3, IBM Plex Mono; latin-subset WOFF2 from fontsource, versions and licences in its `README.md` and `OFL.txt`). Both UIs load them from `/fonts/<name>` only, never a CDN: `serve.py` (`FONT_FILES`) and `host.py` serve an allow-list of exact names without a session (the 401 and sign-in pages need them), and the CSPs keep `font-src 'self'`. Adding or renaming a font file means updating both allow-lists and their tests.
- `scripts/grammar.py` (LanguageTool, stdlib-only, imported by `ci_report.py` and `serve.py`, never by `build.py` except for the three `build.toml` key names) sends text to a server: local requests must bypass proxies, the public API (`PUBLIC_URL`) only on an explicit opt-in (never from `auto`; CI also needs `GRAMMAR_PUBLIC_OK=1`; `serve.grammar_plan` refuses it while sharing unless the owner allowed it), always chunked and throttled by `PUBLIC_LIMITER`. `POST /api/grammar` is edit-role only and `/api/grammar/settings` owner-only through `check_permission`; there is no grammar bus message. Tests mock `grammar.post_form` and must not touch the network.
- `scripts/bibfix.py` (stdlib-only, imports `grammar` only for `Limiter` and `to_utf16`) sends a DOI or title to `api.crossref.org`: only on explicit opt-in (`ci_report.py lint --bib-lookup`, never enabled in the workflow; the editor's Look up click), always through `get_json` (throttled, cached, generic User-Agent without an e-mail), never guessing (title matches need high similarity). It only adds missing fields (`insert_fields` leaves every other byte alone). `POST /api/bib/lookup` is edit-role only through `check_permission`; it writes nothing, the editor applies the returned edit to its open document so Yjs rooms stay consistent. Tests mock `bibfix.get_json` and must not touch the network.
- `scripts/zotero.py` (stdlib-only, imports `bibfix` and `grammar`; `serve.py` imports it, `build.py` never) sends the owner's Zotero API key to `api.zotero.org` (or reads Better BibTeX on `127.0.0.1:23119`): only on an explicit click in the owner's References panel, always through `zotero.get` (throttled by `LIMITER`, generic User-Agent, key only in the `Zotero-API-Key` header, no redirects, errors that name neither URL nor key). The key lives in `ZOTERO_API_KEY` or the 0600 `zotero.json` in the user's config dir, never in the project directory, a reply, the bus or Yjs; `zotero.info()` returns `has_key` only. `/api/zotero`, `/settings` and `/preview` are owner-only (default deny in `check_permission`, so hosted workers, which have no owner, refuse them and the UI hides Zotero); `/apply` is edit-role and network-free, and returns one splice the editor applies. Better BibTeX mode is refused while `SHARE["on"]`. Tests mock `zotero.get` and must not touch the network.
- `scripts/ai.py` (stdlib-only, imports `grammar` only for `Limiter` and `to_utf16`, imported by `serve.py` and `host.py`, never by `build.py` or CI) sends text to the Anthropic API: only after the owner turned it on (`serve.ai_settings`, stored in `ai.SETTINGS_FILE`, mode 600, outside every project) or the operator set `[ai] enabled` in `config.toml`; only on a click, always through `post_json` (no redirects), behind `LIMITER`, with `MAX_TOKENS` and size caps. The key (`ai.env_key()` takes it out of `os.environ` at import so no build or worker inherits it; or the settings file / `config.toml`) is never sent to a client, the bus or a Yjs room, and workers never get it: hosted AI requests stop at the gateway (`Handler.assistant`; per-person, per-workspace and server-wide daily quotas plus a token budget in `ai_usage`, billed failures recorded too). Locally the key stays readable by code a build runs as the owner, so `POST /api/ai` for non-owners needs the owner's `share` consent and sandboxed builds (`ai_sandboxed`), and is edit-role only through `check_permission`; `/api/ai/settings` is owner-only; there is no AI bus message. Model output is untrusted: the schema is checked again in `parse_reply`, edits must name a sent file and quote text found once in the part the model saw, `RC_NAMES` files are never sent or edited for anyone (a build log can name them), the best-effort `UNSAFE` filter drops LaTeX that runs programs, the editor renders it with `textContent` and applies nothing without a click. Document text is data in tagged blocks, never instructions. Tests mock `ai.post_json` and must not touch the network.
- `scripts/ci_report.py` is CI-only and stdlib-only. It reads `out/build-report.json` (written by `build.py`) and writes `out/lint-report.json`. Its `diff` output goes outside `out/`, so the latexdiff PDFs are never published to the release.
- If you rename the workflow file or add shared inputs outside `files/`, update `GLOBAL_INPUTS` in `build.py` and the `paths:` filters in `.github/workflows/build-pdf.yml` together.
- Building needs only Python and a LaTeX distribution; Docker is never required. If this machine has no LaTeX, optionally verify in a throwaway `ubuntu:24.04` container with `apt-get install --no-install-recommends latexmk texlive-latex-extra texlive-plain-generic texlive-fonts-recommended texlive-science texlive-xetex texlive-luatex texlive-extra-utils texlive-bibtex-extra biber chktex latexdiff python3 git`. CI installs the same content two ways: `build` restores a `~/texlive` cache (about 12 s) and on a miss uses trimmed apt (about 70 s); the parallel `texlive-cache` job (`continue-on-error`, never a `needs` of `build`) then installs TeX Live from tug.org with `zauguin/install-texlive` (`cache: false`, packages from `.github/texlive-packages.txt`, which the cache key hashes) and saves the cache. Debian package names map to TeX Live collections there (`python3` and `git` are for the container). If a document adds a LaTeX package, update the apt list in `README.md`, the apt step in the workflow and `.github/texlive-packages.txt`; the TeX Live tree is newer than Ubuntu's, so check a package exists in both.

## Python project

- `requirements.txt` is generated from `uv.lock`, so change dependencies with `uv add` / `uv remove`. The pre-commit hook in `.githooks/` re-exports it. Outside the hook, run `uv export --no-hashes --no-emit-project -o requirements.txt`, with exactly these flags, because CI diffs against that output.
