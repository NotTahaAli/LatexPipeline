# AGENTS.md

`README.md` covers usage; `python scripts/build.py --help` lists flags.

## Layout

- `files/<name>/main.tex` is one document, built to `out/<name>.pdf`. Only directories under `files/` are searched by CI and by default. `bench/` holds local benchmark documents, built with `--source bench`; CI never builds them, and `build.py` keeps their outputs in `out/` when it prunes.
- A document's inputs are everything in its own directory. Keep `.cls`, `.bib`, and figures beside `main.tex`. Files outside it (`\input{../shared/x}`) count for rebuild detection (local mtime and CI `--changed-since`) once a build has recorded them in the document's `.fls` (latexmk `-recorder`, in `.latex-cache/`). A document's first build sees only its own directory.
- `out/` is generated and git-ignored. Every build writes `out/<name>.log`, which holds the result plus the latexmk, LaTeX and BibTeX logs. `build.py` also deletes PDFs and logs whose `main.tex` is gone.
- CI publishes to the GitHub release tagged `pdfs` through `scripts/publish_release.py`. That tag is also the bookmark CI diffs against, so treat it as CI-owned. Moving or deleting it by hand changes what the next run rebuilds.

## Build script

- `scripts/build.py` uses only the Python standard library and must keep working on Windows, macOS, and Linux. Reach for stdlib before adding a dependency.
- `scripts/accel.py` holds the TikZ externalization and `--focus` helpers `build.py` imports (pretex files injected through `latexmk -usepretex`). Keep it stdlib-only and cross-platform too; every accelerated path must fall back to a plain build.
- `scripts/publish_release.py` runs only in CI. It imports from `build.py` and calls the `gh` CLI. It uploads the PDFs and logs in `out/`, so in CI `out/` must hold only this run's output. A failed document then keeps its previous PDF next to the new `.log`. Release file names use reversible `_XX` hex escaping (`asset_name`), and deletion relies on that mapping. Change the naming rule and every existing file on the release gets deleted and re-uploaded under its new name on the next run. The release notes keep their per-document state in a hidden `<!-- latex-pipeline-state: ... -->` comment, so changing that format loses the "PDF from" column for documents not rebuilt in the next run.
- `scripts/serve.py` and `scripts/serve_ui/` are the local editor; CI never runs them. `serve.py` is stdlib-only, cross-platform and must keep working on Python 3.9 (`from __future__ import annotations`; no `match`, no `X | Y` outside annotations). The UI loads libraries only from the pinned CDN imports in `libs.js` and the CSP (`csp()`), with exact versions. Do not import `serve` from `build.py`, `ci_report.py` or `publish_release.py`, and keep editor-only files out of `GLOBAL_INPUTS` and the workflow `paths:`. While sharing is on, treat every non-owner as hostile: LaTeX source is code. Builds get `-norc`, `shell_escape=f`, `openin_any=p`, `openout_any=p` and no unsafe `latexmk_args` (`guarded_read_settings`, `unsafe_latexmk_arg`, `SHARE_ENV`). LuaLaTeX stays allowed by the owner's choice (Lua can write files, so an edit link can run code); the Share dialog must keep saying so; build-config files (`RC_NAMES`) stay owner-only in the PUT API and in Yjs rooms; `visible()` is a whitelist that filters bus messages by document and room; new endpoints and bus message types go through `check_permission` and `visible()`, with a test. Decisions that protect data (leader takeover, deleted files) are made server-side or covered by `tests/collab_check.mjs`.
- `scripts/grammar.py` (LanguageTool, stdlib-only, imported by `ci_report.py` and `serve.py`, never by `build.py` except for the three `build.toml` key names) sends text to a server: local requests must bypass proxies, the public API (`PUBLIC_URL`) only on an explicit opt-in (never from `auto`; CI also needs `GRAMMAR_PUBLIC_OK=1`; `serve.grammar_plan` refuses it while sharing unless the owner allowed it), always chunked and throttled by `PUBLIC_LIMITER`. `POST /api/grammar` is edit-role only and `/api/grammar/settings` owner-only through `check_permission`; there is no grammar bus message. Tests mock `grammar.post_form` and must not touch the network.
- `scripts/bibfix.py` (stdlib-only, imports `grammar` only for `Limiter` and `to_utf16`) sends a DOI or title to `api.crossref.org`: only on explicit opt-in (`ci_report.py lint --bib-lookup`, never enabled in the workflow; the editor's Look up click), always through `get_json` (throttled, cached, generic User-Agent without an e-mail), never guessing (title matches need high similarity). It only adds missing fields (`insert_fields` leaves every other byte alone). `POST /api/bib/lookup` is edit-role only through `check_permission`; it writes nothing, the editor applies the returned edit to its open document so Yjs rooms stay consistent. Tests mock `bibfix.get_json` and must not touch the network.
- `scripts/ci_report.py` is CI-only and stdlib-only. It reads `out/build-report.json` (written by `build.py`) and writes `out/lint-report.json`. Its `diff` output goes outside `out/`, so the latexdiff PDFs are never published to the release.
- If you rename the workflow file or add shared inputs outside `files/`, update `GLOBAL_INPUTS` in `build.py` and the `paths:` filters in `.github/workflows/build-pdf.yml` together.
- Building needs only Python and a LaTeX distribution; Docker is never required. If this machine has no LaTeX, optionally verify in a throwaway `ubuntu:24.04` container with `apt-get install --no-install-recommends latexmk texlive-latex-extra texlive-plain-generic texlive-fonts-recommended texlive-science texlive-xetex texlive-luatex texlive-extra-utils chktex latexdiff python3 git`. CI installs the same content two ways: `build` restores a `~/texlive` cache (about 12 s) and on a miss uses trimmed apt (about 70 s); the parallel `texlive-cache` job (`continue-on-error`, never a `needs` of `build`) then installs TeX Live from tug.org with `zauguin/install-texlive` (`cache: false`, packages from `.github/texlive-packages.txt`, which the cache key hashes) and saves the cache. Debian package names map to TeX Live collections there (`python3` and `git` are for the container). If a document adds a LaTeX package, update the apt list in `README.md`, the apt step in the workflow and `.github/texlive-packages.txt`; the TeX Live tree is newer than Ubuntu's, so check a package exists in both.

## Python project

- `requirements.txt` is generated from `uv.lock`, so change dependencies with `uv add` / `uv remove`. The pre-commit hook in `.githooks/` re-exports it. Outside the hook, run `uv export --no-hashes --no-emit-project -o requirements.txt`, with exactly these flags, because CI diffs against that output.
